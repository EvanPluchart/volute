# Security audit — 2026-10-25

Scope: the whole repository at `b6051a7` (M1 and the updater pulled forward from M4), read by a reviewer who had not written it, then fixed. Volute runs unelevated in the tray all day; it reads other programs' executables, raw mouse input over its icon, and now downloads and runs its own installer.

Nothing high-severity was found. One medium and five low findings were fixed; the rest are information.

## Findings and what was done

| # | Severity | Finding | Fix |
|---|---|---|---|
| 1 | Medium | The update had an integrity check but no authenticity check: `SHA256SUMS` and the installer came from the same release over the same connection, so whoever could publish (a stolen token) or intercept (an extra root certificate) could serve a matching pair, run silently after one click. | Decision 0010: `SHA256SUMS` is signed with an ECDSA P-256 release key through BCrypt; the public key is built in, the private key never enters the repository, and the updater refuses an unsigned release. `xtask dist` refuses to sign with any other key. Tests: a round trip with a throwaway key, a damaged signature and another key are refused. |
| 2 | Low | An executable's icon directory was handed to `LookupIconIdFromDirectoryEx`, which takes no length, so a crafted `idCount` could make Windows read past the resource of someone else's file while it plays a sound. | `icon_directory_fits` requires the header (reserved 0, type 1) and `6 + 14 × count` bytes before Windows reads it; tested. |
| 3 | Low | The tray's private `WM_SHUTDOWN` (`WM_APP + 4`) could be broadcast by any program at the same integrity, removing the icon while Volute ran on: no window and no icon if it had closed to the tray. | The message acts only after Volute itself set `closing` when dropping the tray. |
| 4 | Low | The single-instance names could be squatted by another program of the same user, swallowing every launch and getting foreground rights. | A second launch signals the running instance only if its process runs this same executable (`QueryFullProcessImageNameW`, limited rights); otherwise it starts. Tested. |
| 5 | Low | The installer was hashed by path, then run by path later, from `%TEMP%`, which may be a shared folder if `TEMP` was redirected: another local user could swap it between the check and the run. | Downloads go to `%LOCALAPPDATA%\Volute\Updates` (per user), the checksum is computed from a handle that denies writing and deleting to others, and that handle stays open until the installer has started. Old downloads are removed at the next start. |
| 6 | Low | `--offer-update=X` could make "Update" install any version, including an older one, if the background check had failed. | `Updater::update` installs only a version strictly newer than the running one. |
| 7 | Info | A download that trickles could keep the updater busy for ever (each read has a timeout, the whole had none). | A 10-minute limit on the whole download. |
| 8 | Info | Decision 0005 described a release workflow that does not exist, a test-run rule with an exception it did not state, "no process handle" and "nothing else written". | 0005 rewritten to match the code. |
| 9 | Info | Another app can name its session "System sounds", and any process can pass Volute's event context so its volume changes look like Volute's own. | Kept: the first only changes a label next to that app's own icon; the second only affects which echoes the UI ignores. |

## Checked and fine

* **WinHTTP:** https only, no certificate overrides, redirects off for the check; a long `Location` fails closed; 64 MB cap enforced before writing.
* **Versions and URLs:** digits only, strictly newer, constant host; a forged redirect can only name a version.
* **Checksums:** exact file name, 64 hex digits (now strictly hex), a missing line refuses.
* **Installer launch:** absolute path, `CreateProcess` without search, a folder of its own made with `create_dir`; an installer that asked for elevation would fail rather than prompt.
* **Install kind:** read from Inno Setup's uninstall key, `REG_SZ` only, lengths respected; elevated, all-users and portable copies only open the release page.
* **Start with Windows:** only the `Volute` value, quoted path, NUL-terminated reads.
* **URLs opened:** `https://` only, built from constants, a parsed version or the repository URL.
* **Other executables:** loaded as data files only; network paths skipped; `GetDIBits` buffers sized exactly, sizes capped; every GDI object freed.
* **Session names:** indirect names (`@dll,-id`) are never resolved, so no DLL another app chose is loaded.
* **Raw input:** only the wheel, only over the icon, the union read after its type is checked, nothing logged.
* **Default device:** `SetDefaultEndpoint` at the 11th slot as in EarTrumpet; the interface ID is checked at creation.
* **Microphone:** no capture stream is ever opened (decision 0008).
* **Files:** settings and volumes validated value by value, written atomically; no path from them is ever opened or run.
* **Dependencies:** pinned, crates.io only, no build-time downloads, no TLS or network crate.

## How to repeat it

Read `docs/decisions/0003`, `0004`, `0005`, `0007`, `0008`, `0010`, then every `unsafe` block and every place the updater touches the file system or the network. `cargo test --workspace` covers the fixes above; `cargo test -p volute -- --ignored local_dist` checks a built release the way the updater will.
